# Changelog

All notable changes to this project are documented here.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## Convention: Tool Changes in Every Release

Every tool **addition**, **rename**, or **removal** must be logged in the `[Unreleased]` section at the time of commit.

When a tool is auto-generated by `npm run codegen` from a new backend endpoint:
1. Run `npm run codegen` locally; commit the updated `src/tools/_generated.ts`
2. Add a bullet under `Added` in `[Unreleased]` describing the new tool
3. Update the tool count in the CHANGELOG

When shipping a release:
1. Move `[Unreleased]` → `[X.Y.Z]` (update semver in package.json first)
2. Bump `server.json` to match — **both** the top-level `version` and `packages[0].version` — plus the tool count in its `description`. The MCP registry reads its version from `server.json` (NOT package.json); skipping this fails the registry publish with `cannot publish duplicate version`.
3. Verify tool count matches actual tools registered in `src/index.ts`
4. Commit CHANGELOG + package.json + server.json together
5. Tag: `git tag vX.Y.Z && git push origin vX.Y.Z`

This ensures clients can always see what tools are available in a given version and upgrade decisively.
